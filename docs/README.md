# pgzx documentation site

The site at <https://pgzx.barddoo.com/> is an [Astro](https://astro.build/)
+ [Starlight](https://starlight.astro.build/) project. Prose lives in
`src/content/docs/`; the API reference is the Zig Autodoc bundle.

## Layout

```text
src/content/docs/   prose pages (start/, guides/, build-system/, contributing/)
public/api/         Zig Autodoc output, generated by scripts/sync-api.ts
public/CNAME        pgzx.barddoo.com (GitHub Pages custom domain)
public/favicon.svg
astro.config.mjs    site URL, sidebar, the #A;... link redirect
dist/               build output; this is the GitHub Pages artifact
```

## Hosting

GitHub Pages serves this as a custom-domain site, so the domain root is the site
root and there is no `base` path. Two settings live outside the repository:

- DNS: `CNAME pgzx → barddoo.github.io` for `barddoo.com`.
- Repository Settings → Pages: custom domain `pgzx.barddoo.com`, then enable
  *Enforce HTTPS* once the certificate is issued.

`public/CNAME` is copied into `dist/` and keeps Pages pointed at the domain even
if the setting is ever lost.

## Local preview

```sh
bun install
bun run sync-api    # zig build docs, then copy into public/api (needs PG env)
bun run dev         # http://localhost:4321/
```

`bun run sync-api` shells out to `zig build docs`, so run
`eval "$(../zig-out/bin/pgzx env)"` from the repository root first (or work in a
shell that has it).

## Build

```sh
bun run build       # sync-api + astro build -> dist/
```

`zig build docs` writes only to `zig-out/share/pgzx/docs`; nothing in this
directory is generated in place, so the site can be edited and rebuilt freely.

## Links

There is no `base`, so generated and hand-written links agree: `/<route>/`. API
symbols are linked as `/api/#pgzx.pgzx.<module>.<name>`
(`#pgzx.<name>` for declarations in the root `src/pgzx.zig`), which is the
`fullyQualifiedName` format the Autodoc UI itself emits. `#A;pgzx:...` is the
pre-0.17 format; the redirect in `astro.config.mjs` rewrites those old links to
the current anchors, and `404.md` drops a leftover `/pgzx` prefix for links that
still arrive from the old `barddoo.github.io/pgzx/` URLs.

Two things in `astro.config.mjs` are load-bearing and look removable:

- `devApiIndex` exists because Vite serves `public/` as plain files and does not
  resolve directory indexes, so `/api/` 404s in dev even though Pages serves it
  fine. It only runs under `astro dev`.
- The config must stay an **object**: with `defineConfig(({ command }) => ...)`,
  Astro 7.4's dev server answers 404 for every route (builds still work, which
  makes it a nasty one).
